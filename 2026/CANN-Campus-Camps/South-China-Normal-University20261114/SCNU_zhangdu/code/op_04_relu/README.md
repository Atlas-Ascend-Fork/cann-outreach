## 算子实现介绍

一、 算子功能与规格
本算子基于 Ascend C 编程语言原生开发，在昇腾 NPU 硬件上实现了 ReLU（线性整流函数）激活算子。
计算公式：y = max(0, x)
输入规格：张量 x，维度形状支持 (8, 2048) 与 (2048, 2048) 等变长场景，数据类型支持 float32 / float16，格式为 ND。
输出规格：张量 y，形状与数据类型完全同输入保持一致，格式为 ND。
二、 Host 侧实现（Tiling 与推导）
Host 侧代码负责算子的图推导与 Tiling 切分策略：
形状与类型推导：实现 InferShape 与 InferDataType 逻辑，保证逐元素算子的输出与输入完全一致。
动态 Tiling 策略：
总长计算：遍历输入 x 的 Shape，动态计算总元素个数（totalLength）。
内存防爆：针对大规模输入（如 2048x2048），动态放大切分数 tileNum（如从 8 提升至 32），防止单次搬运数据过大导致 NPU Unified Buffer (UB) 溢出。
核数配置：配置启动 8 个 AI Core 以实现多核并行计算，将切分参数打包进 ReluTilingData 下发给 Device 侧。
三、 Kernel 侧实现（高可靠与极速流水线）
Kernel 侧代码（relu.h）采用标准的三段式流水线架构，并针对大 shape 测试用例进行了鲁棒性加固：
精准多核切分与尾核处理：使用向上取整计算每核理论长度，若当前核起始偏移越界则直接退出，若为尾核则动态截断，确保 (2048, 2048) 等无法被 8 整除的数据量不丢数据、不越界。
32 字节对齐防护：针对向量计算与 DataCopy 的硬件要求，在代码中动态计算 copyLength。当数据量无法被 32 字节整除时，向上补齐读取长度，彻底避免了因非对齐内存访问导致的 Runtime Error。
极致性能加速：
开启 BUFFER_NUM = 2 的双缓冲（Double Buffer）机制，使得 MTE2（数据搬运）与 Vector（向量计算）单元完美重叠，掩盖搬运延迟。
直接调用底层硬件原语 AscendC::Relu，一步完成 max(0, x) 运算，大大降低了指令调度开销，实测单测试点耗时逼近最优基准。
