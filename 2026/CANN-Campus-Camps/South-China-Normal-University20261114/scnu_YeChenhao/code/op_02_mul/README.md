## 算子实现介绍

本实验基于 Ascend C 编程语言，在昇腾 NPU 上完成矢量乘法算子 z = x * y 的原生开发。输入 x、y 与输出 z 均为 (8, 2048) 的 ND 张量，支持 float32 与 float16，共 16384 个元素、合计 64KB。工程采用标准自定义算子工程结构：op_host 侧负责 Tiling 与算子注册，利用 tiling key 模板区分 float 与 half 两个实例；op_kernel 侧实现核函数，通过 REGISTER_TILING_DEFAULT 与 GET_TILING_DATA_WITH_STRUCT 读取 tiling 参数。

实现上以 32B 对齐为切分粒度（float 为 8 元素、half 为 16 元素一块），切分计算全部在 host 侧完成，只向 kernel 传“每核块数”“余数块数”两个整数，因此 kernel 内没有除法、取模和循环，也没有分支发散。每核只做一次大块搬运：连续读入本核负责的 x、y 切片，调用一次 AscendC::Mul 完成逐元素相乘，再整块写回 z；三块数据各占独立 UB，不做就地覆盖，避免读写冲突。同步只保留两对硬件事件——MTE2 到 V 保证搬入完成后再计算，V 到 MTE3 保证计算完成后再搬出；相比官方参考的 TQue 队列方式，省掉了 AllocTensor、EnQue、DeQue、FreeTensor 的队列事件开销。

性能优化沿两条线索展开。一是削减每核固定开销：把参考实现的“8 核 × 16 次小循环”改成“单核单块大搬运”，指令数从数十条降到四条，同时消除小循环之间的流水气泡。二是调整并行度：启动核数由平台 AIV 全量改为固定值，实测扫描 8、4、2 三档，4 核最好，说明该规模下瓶颈是每个 block 的固定开销而非带宽。此外 host 侧 Tiling 去掉了平台信息查询与内存容量查询，只保留形状、数据类型和切分计算，缩短了每次调用的 host 路径。经上述改动，算子用时相对初始模板显著下降，计算结果与 numpy 参考实现一致，满足相对误差 1e-4、绝对误差 0.1 的验收要求。
