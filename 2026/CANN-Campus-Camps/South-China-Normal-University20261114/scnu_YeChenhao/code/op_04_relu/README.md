## 算子实现介绍

本算子基于 Ascend C 在昇腾 910B 上实现 ReLU（y = max(0, x)），支持 float32 与 float16 输入，针对 (8, 2048) 与 (2048, 2048) 两种 shape 做了端到端优化。实现分为 Host 侧 Tiling 与 Kernel 侧两级。Tiling 侧先把输入展平成一维，用成本模型 T(N) = A + c·N + 2B/(N·BW) 选择启动核数；其中每启动一个 block 的固定开销 c 实测约 0.194 μs，单核有效搬运带宽按 30 GB/s 估算，因此大 shape 并非核越多越好，块数被限制在 20 以内，既能跑满带宽，又不会让块调度开销过大反而拖慢性能。每核负责的数据量按 512B 对齐，因为 GM 偏移只做 32B 对齐时有效带宽只有约七成，按 512B 对齐才能跑满；尾核数据不足时由 Kernel 侧按实际剩余元素裁剪，保证不漏算也不越界。UB 侧同样按 512B 对齐切块，并保证每核至少 8 块，以降低流水填充与排空的开销。

Kernel 侧的核心是三级软件流水。一次 InitBuffer 申请四块 UB，前两块作为搬入 ping-pong 缓冲，后两块作为搬出 ping-pong 缓冲，输入和输出缓冲区完全分离，再用 8 个硬件事件 id 分别管理四类依赖：搬入完成可计算、计算读完可覆盖、计算写完可搬出、搬出完成可覆盖。主循环每轮先预取第 i+1 块，再计算第 i 块，最后写回第 i 块，使 MTE2 搬入、Vector 计算、MTE3 搬出三条流水真正并行，避免传统写法中逐块同步造成的串行等待。计算部分用单条向量 Maxs 指令完成，按 repeatTimes 上限 255 分段，保证一屏数据一次下发。搬运在整块 32B 对齐时采用 DataCopy 快路径，只有尾部残块才回退到 DataCopyPad。对于 16384 元素的小 shape，改为每核只处理一块，直接一次搬入、一次计算、一次搬出，省掉多块流水的填充与排空。最终两个测试点均以 0.00% 误差通过，用时约 4.1 μs 与 15.6 μs。
